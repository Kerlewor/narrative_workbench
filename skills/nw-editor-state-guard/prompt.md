# nw-editor-state-guard

## Skill 名称

编辑器状态守门人 — 专门管理章节编辑器与 AI 生成过程中的危险状态。

## 用途

小说写作 App 最容易出事故的地方是编辑器：用户写了很久然后误触返回、AI 覆盖原文、生成失败后原稿消失、采纳润色后无法恢复、切换章节后编辑状态混乱。本 Skill 定义铁律级别的状态安全规则，任何涉及编辑器或 AI 生成结果的代码改动都必须遵守。

## 适用场景

- 实现或修改章节编辑页
- 实现或修改 AI 润色/生成/续写功能
- 实现章节切换、应用切后台、页面返回等导航行为
- 实现候选稿对比、采纳、回滚功能
- 代码审查阶段，检查编辑器相关代码是否违反安全规则

## 触发条件

- 编写或修改任何与 `ChapterEditor`、`AIResult`、`DraftManager`、`VersionHistory` 相关的代码
- 涉及页面导航（Navigation、NavPathStack、router.back）与编辑器状态的交互
- Review 阶段审查前端代码
- 用户明确要求检查编辑器状态安全性

## 必读输入

- `nw-product-flow-architect` 产出的页面流转表
- 当前编辑器的状态管理代码（如已有）
- narrative_workbench v0.5.0 中的"版本化候选稿与决策日志"设计思路

## 铁律规则

以下规则是硬约束，违反即视为代码缺陷：

### 铁律 1：原文不可侵犯

- 原文（canonical body text）永远不能被 AI 直接覆盖。
- AI 生成结果必须写入独立的候选稿存储（`story/runtime/` 或对应 App 内独立数据表）。
- 用户必须显式点击"采纳"后，候选稿才替换原文。

### 铁律 2：每次采纳前生成可回滚版本

- 在用户点击"采纳"前，当前原文必须自动保存为一个可回滚的历史版本。
- 历史版本列表必须可查看、可按时间排序。
- 支持"恢复到任意历史版本"。

### 铁律 3：未保存编辑必须二次确认

- 编辑页退出前检测是否有未保存的修改。
- 存在未保存修改时，必须弹出保存确认对话框：
  - **保存**：保存修改后退出
  - **不保存/丢弃**：放弃修改后退出
  - **取消**：留在当前页面
- 不允许静默丢弃或静默自动保存（除非用户已在设置中开启自动保存）。

### 铁律 4：AI 请求失败不破坏正文

- AI 生成请求超时/网络错误/服务端错误 → 原文不受任何影响。
- 错误信息展示后，页面状态回到生成前。
- "重新生成"按钮可用。

### 铁律 5：切换章节前必须保存或提示

- 从编辑页切换到另一个章节前，检查未保存修改。
- 有未保存 → 弹出保存确认（同铁律 3）。
- 已保存 → 直接切换，切换后编辑器状态完全刷新（不残留上一章的 undo 栈、光标位置等）。

### 铁律 6：AI 生成中允许退出，但任务结果可恢复

- AI 正在生成时用户点击返回 → 允许退出页面。
- 后台继续执行生成任务（不取消）。
- 用户再次进入该章节时 → 自动检测是否存在完成但未查看的生成结果 → 提示"上次的 AI 生成结果已就绪，是否查看？"
- 生成失败时 → 进入章节后在状态栏提示上次生成失败，可重新发起。

### 铁律 7：草稿与正文隔离

- 编辑中的内容存储在草稿层（draft），与已发布的正文（canonical）隔离。
- 只有用户显式"保存/发布"时，草稿才提升为正文。
- 草稿在应用卸载前不应丢失（持久化到本地存储）。

### 铁律 8：采纳不可逆但可回滚

- 用户采纳 AI 候选稿后，正文变为候选稿内容。
- 采纳前的原文自动加入历史版本列表。
- 用户始终可以通过历史版本回滚到采纳前的状态。

## 输出格式

### 编辑器安全检查清单

每次编辑器相关代码变更完成后，逐项勾验：

```markdown
- [ ] 原文不被 AI 覆盖
- [ ] 采纳前自动保存历史版本
- [ ] 未保存退出有二次确认
- [ ] AI 失败不破坏正文
- [ ] 切换章节前保存/提示
- [ ] AI 生成中可退出 + 结果可恢复
- [ ] 草稿与正文隔离
- [ ] 采纳后可回滚
- [ ] 自动保存逻辑（如已实现）有效期 >= 30 天
- [ ] 历史版本列表可正常查看和恢复
```

### 状态安全矩阵

| 用户状态 | 操作 | 预期行为 |
|---|---|---|
| 正在编辑，有未保存修改 | 点击返回 | 弹出保存确认对话框 |
| 正在编辑，有未保存修改 | 切换到其他章节 | 弹出保存确认对话框 |
| 正在编辑，无未保存修改 | 点击返回 | 直接返回上一页 |
| AI 生成中 | 点击返回 | 退出页面，后台继续任务 |
| AI 生成中 | 关闭 App | 任务标记为中断，下次打开提示重试 |
| AI 生成完成，未查看 | 进入章节 | 提示"结果已就绪，是否查看" |
| AI 生成失败 | 进入章节 | 显示失败状态，提供重新生成按钮 |
| 查看候选稿中 | 点击返回 | 关闭候选稿，回到编辑器 |
| 已采纳候选稿 | 查看历史版本 | 可看到采纳前的原文版本 |
| 恢复历史版本中 | — | 当前正文进入历史版本，选中版本成为新正文 |

## 禁止事项

- 禁止 AI 生成结果直接写入 `chapters/` 目录或对应 App 正文表。
- 禁止在未保存情况下静默退出编辑页。
- 禁止采纳后不创建回滚点。
- 禁止切换章节时不清空编辑器状态（undo 栈、光标、选区必须重置）。
- 禁止 AI 生成失败后自动重试而不经用户确认。

## 与主工作流的关系

- 是否可用于 Writer：否
- 是否可用于 Polish：否
- 是否可用于 Review：是 — Review Agent 审查前端代码时应逐项对照本 Skill 的铁律清单
- 是否可用于 Fixer：是 — Fixer 修复编辑器相关 bug 时必须遵守本 Skill 的规则
- 是否可用于大纲搭建：是 — 用于鸿蒙 App 的需求梳理阶段，定义数据安全需求
