# nw-product-flow-architect

## Skill 名称

产品流程架构师 — 负责页面信息架构和前进后退逻辑设计，不写代码。

## 用途

在编写任何 ArkUI 代码之前，先输出完整的页面清单、导航层级、状态流转表和返回行为规范。确保 AI 开发者（和后续编码 Agent）在动手前有清晰的产品交互蓝图。

## 适用场景

- 新增功能模块前，需要先理清页面关系和用户路径
- 多人/多 Agent 协作时，需要一份共享的页面交互规约
- 产品评审时，需要快速对齐"哪些页面、怎么跳、返回到哪"
- 从 narrative_workbench Markdown 工作流向图形界面迁移时，需要重新设计信息架构

## 触发条件

- 用户明确要求设计页面流程、导航结构
- `story/runtime/*.plan.md` 声明需要产品流程架构
- 新建 HarmonyOS App 功能模块时

## 必读输入

- 项目功能清单（当前 narrative_workbench 能力列表）
- 目标用户画像（普通小说作者，非技术用户）
- 现有页面/组件列表（如有）

## 工作步骤

1. 梳理功能清单：列出 App 所有需要承载的能力，区分 MVP 必须做和暂不做的。
2. 输出页面清单：每个页面的名称、用途、所属层级。
3. 输出页面层级树：从启动页开始的完整嵌套关系。
4. 为每个页面定义：入口（从哪里来）、出口（到哪里去）、主要操作按钮。
5. 单独输出返回行为表：顶部返回按钮行为、系统返回手势行为、未保存内容处理方式、AI 任务进行中退出方式。
6. 输出状态流转表：涵盖正常路径和异常路径（空状态、加载中、错误、无网络）。
7. 输出页面跳转图（文本箭头图）。

## 输出格式

### 页面清单

| 页面名称 | 用途 | 层级 | MVP |
|---|---|---|---|
| 启动页 | 品牌展示/初始化检查 | L0 | 是 |
| ... | ... | ... | ... |

### 页面层级树

```text
启动页
  └── 作品库 (L1)
        └── 项目首页 (L2)
              ├── 章节列表
              │     └── 章节编辑页 (L3)
              ├── 角色设定 (L2)
              ├── 世界观/资料库 (L2)
              └── 项目设置 (L2)
全局设置 (L1, 从任意页进入)
```

### 页面入口出口表

| 页面 | 入口 | 出口 | 主要按钮 |
|---|---|---|---|
| 作品库 | 启动页自动跳转 | → 项目首页 | 新建作品、搜索 |
| ... | ... | ... | ... |

### 返回行为表

| 当前页面 | 用户操作 | 下一状态 | 返回行为 |
|---|---|---|---|
| 章节编辑页（无未保存） | 点击返回 | 章节列表 | 直接返回 |
| 章节编辑页（有未保存） | 点击返回 | 保存确认弹窗 | 保存/丢弃/取消 |
| 章节编辑页（AI 生成中） | 点击返回 | 可退出页面 | 任务保留后台，可重新进入查看 |
| ... | ... | ... | ... |

### 状态流转表

| 当前状态 | 触发事件 | 下一状态 | UI 表现 |
|---|---|---|---|
| 章节加载中 | 网络请求完成 | 章节就绪 | 编辑器显示正文 |
| 章节加载中 | 网络请求失败 | 加载失败 | 错误提示 + 重试按钮 |
| AI 生成中 | 生成完成 | 候选稿就绪 | 显示对比入口 |
| AI 生成中 | 生成失败 | 生成失败 | 错误信息 + 原文不受影响 + 重新生成按钮 |
| ... | ... | ... | ... |

### 页面跳转图

```text
作品库 ──(点击作品)──→ 项目首页 ──(点击章节)──→ 章节编辑页
                          │                        │
                          │                        ├──(点击AI操作)──→ AI操作面板(底部)
                          │                        │
                          │                        └──(点击返回)──→ 项目首页
                          │
                          ├──(点击角色)──→ 角色设定
                          └──(点击设置)──→ 项目设置

全局设置 ←──(任意页-设置图标)── 任意页面
```

## 禁止事项

- 不要跳过流程设计直接写 ArkUI 代码。
- 不要让 AI 同时承担"写代码"和"设计流程"两个职责。
- 不要假设用户（普通作者）理解 Claude Code/Codex 的使用习惯。
- 返回行为不要用"系统默认"，必须逐页明确。

## 与主工作流的关系

- 是否可用于 Writer：否（这是产品设计工具，不是写作工具）
- 是否可用于 Polish：否
- 是否可用于 Review：否 — 但 Review 阶段可读取本 skill 产出的页面规约来审查前端代码
- 是否可用于 Fixer：否
- 是否可用于大纲搭建：是 — 用于鸿蒙 App 的产品需求梳理阶段
