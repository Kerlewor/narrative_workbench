# nw-user-journey-tester

## Skill 名称

用户路径测试员 — 以普通用户身份走完整流程，发现逻辑混乱、状态异常和体验断层。

## 用途

AI 每完成一个功能模块，不是只检查"页面能不能打开"，而是以普通作者身份跑完整用户路径，输出通过/失败/体验问题的结构化测试报告。模拟真实用户会怎么点击、在什么状态下退出、遇到什么问题后放弃使用。

## 适用场景

- 每个功能模块完成后
- 发版前的回归测试
- 收到用户反馈"不好用"但无法定位问题时
- 新人接手项目时，快速了解 App 的实际使用流程

## 触发条件

- 用户明确要求"测试用户路径"或"走一遍流程"
- 代码审查/发版前 checklist
- 新增核心功能（编辑、AI 生成、设置 API）后
- `nw-product-flow-architect` 产出页面流程后，用本 Skill 验证实现是否正确

## 必读输入

- `nw-product-flow-architect` 产出的页面流转表和返回行为表
- `nw-editor-state-guard` 的铁律规则清单
- 当前可运行的 App 版本（或可预览的页面组件）
- 如无运行环境，至少需要所有已完成页面的代码

## 测试路径

### 路径 A：新用户首次使用

```text
安装 App → 首次启动（欢迎/权限授权）
  → 进入作品库（空状态）→ 点击"新建作品"
  → 输入书名、选择类型 → 确认创建
  → 进入项目首页（空章节列表）→ 点击"新建第一章"
  → 进入编辑器 → 输入一段文字 → 点击保存
  → 点击 AI 操作入口 → 选择"AI 润色"
  → 等待生成完成 → 查看候选稿
  → 对比原文与候选稿 → 采纳
  → 退出编辑器 → 确认章节列表显示第 1 章
```

**每步检查点：**

| 步骤 | 检查项 | 通过标准 |
|---|---|---|
| 首次启动 | 启动速度 | < 3 秒进入作品库 |
| 空作品库 | 空状态展示 | 有引导文案 + 新建按钮 |
| 新建作品 | 表单交互 | 书名必填校验、类型选择器正常、键盘弹起不遮挡 |
| 空项目首页 | 空状态展示 | 有引导文案 + 新建章节入口 |
| 编辑器 | 键盘弹起 | 工具栏随键盘上移，正文不遮挡 |
| 保存 | 保存反馈 | 有明确的"已保存"提示（toast/状态栏） |
| AI 润色 | 生成等待 | 有进度反馈 + 可取消 |
| 查看候选稿 | 对比视图 | 原文与候选稿并排或可切换 |
| 采纳 | 历史版本 | 采纳后原文变更，历史版本可查 |
| 退出 | 状态检查 | 无未保存提示（已保存），直接返回 |

### 路径 B：已有作者继续写作

```text
打开 App → 作品库（已有作品）→ 点击上次在写的作品
  → 项目首页 → 在章节列表中找到上次编辑的章节（标记"上次编辑"）
  → 进入编辑器 → 光标定位在上次编辑位置（或章节顶部）
  → 继续输入内容 → 使用 AI 续写
  → 查看候选稿 → 部分采纳（只采纳其中几段）
  → 继续手动修改 → 保存
  → 退出 → 切换另一章 → 确认未保存提示出现
```

**每步检查点：**

| 步骤 | 检查项 | 通过标准 |
|---|---|---|
| 打开 App | 上次状态恢复 | 作品库显示上次浏览的作品（或保持原样） |
| 进入作品 | 章节列表 | 上次编辑的章节有视觉标识 |
| 进入编辑器 | 光标/阅读位置 | 可定位到上次编辑位置 |
| AI 续写 | 上下文 | AI 能获取到前文（检查生成内容是否接得上） |
| 部分采纳 | 选择交互 | 可选择段落范围，只采纳选中部分 |
| 切换章节 | 未保存提示 | 弹出保存确认，三个选项都有效 |

### 路径 C：配置自己的 API

```text
从任意页面 → 打开全局设置 → API 配置
  → 选择模型供应商（至少 2 个选项）
  → 输入 API Key → 点击"验证连接"
  → 验证成功 → 返回写作页
  → 发起一次 AI 生成 → 确认使用的是用户配置的 API
```

**每步检查点：**

| 步骤 | 检查项 | 通过标准 |
|---|---|---|
| 设置入口 | 可达性 | 从主要页面都能进入设置 |
| 供应商选择 | 选择器交互 | 选项展开、选中反馈正常 |
| API Key 输入 | 安全性 | 输入框为密码类型（掩码显示）、支持粘贴 |
| 验证连接 | 反馈 | 成功/失败有明确提示，失败说明原因 |
| 返回写作 | 设置生效 | AI 生成时使用用户配置的 API（而非默认/内置 key） |

### 路径 D：异常恢复

```text
场景 1：生成中网络断开
  正在 AI 生成 → 模拟断网 → 生成失败
  → 检查正文是否完好 → 检查"重新生成"按钮可用
  → 恢复网络 → 重新生成 → 成功

场景 2：编辑中突然退出
  正在编辑（有未保存内容）→ 模拟返回/关闭 App
  → 重新打开 App → 进入同一章节
  → 检查草稿是否存在 → 检查是否有"恢复未保存内容"提示

场景 3：关闭 App 后回来
  AI 生成中关闭 App → 重新打开 → 进入章节
  → 检查是否有生成结果通知或任务状态提示

场景 4：快速切换
  章节编辑页 → 返回 → 立即再进入 → 状态是否正常
```

**每步检查点：**

| 场景 | 检查项 | 通过标准 |
|---|---|---|
| 生成中断网 | 原文安全 | 正文完好无损，无 AI 垃圾数据渗入 |
| 生成中断网 | 恢复能力 | 重新生成按钮可用，点击后正常发起 |
| 编辑中退出 | 草稿恢复 | 重新进入有草稿恢复提示 |
| 关闭后回来 | 任务状态 | AI 任务状态正确显示（完成/失败/中断） |
| 快速切换 | 状态隔离 | 页面不残留上一轮的状态 |

## 输出格式

### 测试报告

```markdown
## 测试路径：[路径名称]
## 测试日期：[YYYY-MM-DD]
## App 版本/commit：[version]

### 通过项
- [x] 步骤描述 — 符合预期
- [x] ...

### 失败项
- [ ] 步骤描述 — **问题**：具体现象。**预期**：应该怎样。**严重程度**：P0/P1/P2
- [ ] ...

### 体验问题（非阻断）
- 步骤描述 — 功能正常但体验不好：具体说明
- ...

### 总结
- 通过：X/Y 项
- 失败：X 项（P0: X, P1: X, P2: X）
- 体验问题：X 项
```

### 严重程度定义

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 | 阻断使用：数据丢失、崩溃、死循环、原文被覆盖 | AI 结果覆盖了用户原文 |
| P1 | 核心流程损坏：功能可绕过但体验严重受损、状态卡死需杀进程 | 未保存退出没有提示，草稿丢失 |
| P2 | 非核心路径异常：边缘场景、UI 不一致、空状态缺失 | 历史版本列表为空时没有空状态 |

## 禁止事项

- 禁止只检查"页面能不能打开"——必须模拟完整用户操作链。
- 禁止跳过异常路径——正常路径谁都会测，异常路径才是事故源头。
- 禁止用"应该没问题"代替实际验证。
- 禁止在测试报告中省略复现步骤。

## 与主工作流的关系

- 是否可用于 Writer：否
- 是否可用于 Polish：否
- 是否可用于 Review：是 — 每个功能模块 Review 阶段必须跑对应测试路径
- 是否可用于 Fixer：是 — Fixer 修复后必须重跑失败的测试项
- 是否可用于大纲搭建：否

## 知识库依赖

> 本 Skill 不依赖 narrative_workbench 项目知识库。

- 是否需要 knowledge_index.py 查询：否

## 内置知识声明

- 是否包含领域事实数据：否 — 本 Skill 是用户测试方法论。测试路径基于 narrative_workbench 的功能清单设计，铁律预期来自 `nw-editor-state-guard`。
